# REMAINING / REGRESSIONS — RANKED
**U1 HIGH — accepted measurements can come from a replacement listener after verified readiness (Q8 remains open).** scripts/ab-spill.ts:266–286 sets serverClosed but uses it only during load/props; :289–300 settles, tokenizes and runs warmup/reps without reacting to later close or rechecking ownership. Executed fake launch: all three initial owner checks correct, child closes during settle, replacement serves subsequent requests. Result: **error=null, 2 reps accepted, 4 replacement operations (tokenization + warmup + 2 reps)**. Fix: abort the shared controller on unexpected child close/error, verify identity/ownership before measurement requests, and reject all responses after ownership loss; keep cleanup limited to the owned identity.

**U2 MED — pre-spawn owner query fails open on ambiguous/unavailable results.** ab-spill.ts:57 emits a PID only for exactly one listener; :60 returns null for empty output. Both zero listeners and multiple IPv4/IPv6 owners (or a suppressed Get-NetTCPConnection failure) therefore look free at :264. Post-health checks normally reject later, but a conflicting/unknown port can already cause a model launch. Fix: return explicit none/owned/ambiguous/unavailable states, make OS-query errors terminating, and spawn only on a positively verified no-listener result. Existing tests exercise a numeric foreign owner, not this ambiguity.

**U3 MED — top-level device metadata can name a different adapter than the HIP run.** dc4bb13 scripts/run-session.ts:144 chooses `dev=pickDiscreteDevice(devs)` independently from the forced ROCm0 gpuDevice(:145); the dump still stores `device: dev` (:217). On a multi-device HIP host where the preferred discrete adapter is ROCm1, requests/planning use ROCm0 but exported top-level device describes ROCm1. Fix: derive both selected device object and id from the same backend gate, and persist that selection consistently. No real multi-GPU probe was performed.
