# W4G executable acceptance tests

Created only `tests/review-w4g/acceptance.test.ts` and this mapping document. No existing files edited, no GPU/inference, no commits. The test file exercises production APIs with synthetic measured rows; it imports only model metadata from the existing session-single JSON fixture. No production behavior is mocked.

Validation: `npx vitest run tests/review-w4g` — **1 file passed; 24 expected failures; 0 unexpected failures** (2026-09-27, 22:43 local run). `npx tsc --noEmit --pretty false` also passed on the final validation run. All acceptance cases use `it.fails`; remove a marker once that case's complete contract passes. The `beforeAll` fixture sanity checks are ordinary assertions, so invalid baseline fixtures do not silently count as successful expected failures.

The first run reported 23 expected failures and one unexpected pass: another worker had integrated repeat collapsing into componentScores while these tests were being written. G01 retains the now-passing repeat/n assertions and also checks the same gap's still-missing heuristic/coverage presentation. This is explicitly documented in the test; it is not evidence that repeat handling remains broken.

## Fixture and output contracts for the engine author

- G06 proposes `verdicts` input `allRuns` containing every run, with `runId`, optional `supersededBy`, `startedAt`, `endedAt`; candidate `runs` contains latest rows only. Its expected behavior is a critical historical device-loss insight after a successful retry. This tests the interpreter handoff, not SQL history retrieval.
- G07b proposes `planningSnapshot: {ramFloorBytes, mmapCreditBytes}`. G07 deliberately supplies no verified planning budget and makes in-use unavailable; it accepts omitted headroom, explicit unavailable/not-evaluable text, or an explicitly named per-PID-versus-total basis, but rejects invented numeric planning headroom.
- G08 adds `ModelMeta.baseModelId` and `fineTuneId`; identical architecture/parameter count with different fine-tune IDs cannot establish quantization equivalence. G09 proposes session `stopReason: 'user-cap'`.
- G10b/G11 define the expected `decisionTrace` adapter in the test: `scoringRung`, `eligibleSet` with failing rule IDs, `neutralizations`, `tieBreakChain`, `rulesVersion`, `thresholdsUsed`, and alternative decisions with configId/ruleId. Field spellings may be adapted to the engine author's schema while preserving the assertions. No synthetic output trace is supplied to make the tests pass.
- G10 checks catalog text semantically, with two patterns per ID, and requires `RULES_VERSION === 'interp-2'`. Assertions are soft so a stale version does not hide the text mismatches. Exact prose is not prescribed, but each named policy must be recognizable.
- G12 includes both model competitors and alternative generation configs, and inspects actual reasons/whyNot/best.gen.reason. It does not pass vacuously on an empty whyNot list.
- G14 uses the uncertainty helper as an independent boundary oracle, then checks actual interpreter output at 1/3, coding 2/3, and a one-item failed category. G14b uses [10,11.7]: spread/median =15.67%, spread/max =14.53%, so only the correct denominator warns.

This file supplies at least one executable scenario for each of the 15 ranked gaps, plus the requested split scenarios. It does not claim exhaustive coverage of every subfinding: renderer critical-card retention, storage SQL, runtime template acceptance, every action variant, and truncation production remain additional acceptance work. Expected-failure markers deliberately turn a newly passing contract into an actionable failing test until its marker is removed; they are not evidence that the application conforms today.
