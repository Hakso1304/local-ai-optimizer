# REMAINING FINDINGS — RANKED
**S1 HIGH — descendant PID reuse can kill a foreign process; creation-time windows are not identity checks.** src/core/runtimes/llamacpp/index.ts:429–452 caches discovered records but alivePids/isAlive checks only numeric PID, then kills that number without re-reading its creation time. Executed fake seam: owned descendant exits and an unrelated same-name process reuses PID909 before liveness check; kill(909) is called. Second executed case: original parent exited 100 ms ago, its PID is reused, foreign child is born now; the +1000 ms ownership window admits that child and kills it. Overlapping unloads duplicate kill calls and can increase this race. Fix: single-flight unload; bind root and descendants to verified creation identity/handles, revalidate at apply, and fail closed on ambiguous ancestry; prefer an owned Windows Job Object. Never use a timing window or process name as proof of ownership. Sync killSync's post-exit window (:488–490) needs the same policy.

**S2 HIGH — failed ownership enumeration is not a fatal cleanup failure.** llamacpp/index.ts:437 awaits descendants without wrapping failure as ServerStuckError. Executed injected `descendants()` throwing `CIM failed`: unload rejects ordinary Error with fatal=false, root retained. session.ts:283 catches nonfatal unload errors; backendFor(:269–276) can log and switch backend despite unreaped old ownership. Fix: classify every inability to verify owned-tree exit as fatal, preserve handles/identity, and prevent switching/loading until cleanup is confirmed. This is distinct from the correctly handled known-survivor test.

**S3 HIGH — replay repairs an incoherent partial origin into “original” proof.** scripts/prove-quality-rows.ts:103 trusts prior.origin over prior.originalPromptHashPresent; :107 does not require coherence with that flag, required firstReplayAt shape, or mode. Executed 120 rows with a prompt hash and `{mode:'runtime', originalPromptHashPresent:false, status:'original', origin:{generationPromptHashPresent:true,lineage:[]}}` (firstReplayAt absent). Direct contract would reject them. Replay accepts them, produces **proved=120/reconstructed=0**, overwrites flag/status to true/original, supplies the missing timestamp, and public verdicts accepts both OFF and low. Fix: validate complete root provenance and all redundant fields before rendering; inconsistent/partial evidence must reject or remain reconstructed, never be upgraded. Keep immutable root identity separate from replay output. Normal replay×3 closure does not cover malformed/migrated origin records.
