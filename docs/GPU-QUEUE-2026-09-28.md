# GPU queue — command lines (2026-09-28)

S3 runs these one at a time, only after Fable/Astra releases each one. Only one GPU user at a time; nothing else starts while an item is running.
Durations are estimates from this host's measured speeds: 8B ≈ 90 t/s, 14B ≈ 54 t/s, Gemma-4 ngl 19 ≈ 29 t/s, Qwen3.8 ngl 49 ≈ 10 t/s at 8K.
Session ids are not fixed: the launcher takes the id from the run's `SESSION_ID`/`session:started` log line. Ids shift with failed launches, so never use the latest DB row as the export identity. The evidence file name is the label, since the DB has no label column.

## Manifest launch setup (PowerShell 5.1)

Every `run-session.ts H` item below uses `measurement-launcher.ts`. The launcher hashes the snapshot ZIP, Node, dependency locks, tsx, launcher, runner, exporter, selected runtime executable and DLLs, and model. It verifies them before and after the run, owns and reaps the runner, reads its session ID from its own log, and exports after teardown. HIP device check (4) and standalone A/B (5, 6) have no app session ID and must use their own released-snapshot/preflight/teardown gate; they cannot use this session launcher.

Run this setup inside the extracted immutable snapshot after setting `$QueueZip` to its actual existing ZIP. Each item command below passes an argv array through a UTF-8 JSON config file, so PowerShell never sends JSON as native arguments. The helper appends mandatory cap, RAM floor, backend and existing absolute DB path. Labels are single use; retries get a new label.

Before each released item, verify zero `llama-server.exe`, `typeperf.exe`, `run-session` and `ab-spill` processes; no unified-memory environment key in Process, User or Machine scope in any casing; at least 12 GiB available host RAM; the expected RX 9070 XT adapter and idle VRAM baseline; and at least 60 seconds idle since teardown. Stop on ambiguity or a surviving process. The session launcher repeats its own RAM/process/hash checks immediately before spawning. The snapshot ZIP, `HEAD.txt`, vendor junction, dependencies and model path must match the release manifest. Standalone items need their own equivalent recorded gate.

```powershell
$QueueRoot = (Resolve-Path -LiteralPath .).Path
$QueueHead = (Get-Content -LiteralPath (Join-Path $QueueRoot 'HEAD.txt') -Raw).Trim()
$QueueZip = 'E:\Product_1\snapshots\REPLACE-WITH-RELEASED-SNAPSHOT.zip'
$QueueDb = Join-Path $env:APPDATA 'local-ai-optimizer-dev\optimizer.db'
if (!(Test-Path -LiteralPath $QueueZip -PathType Leaf)) { throw "snapshot ZIP missing: $QueueZip" }
if (!(Test-Path -LiteralPath $QueueDb -PathType Leaf)) { throw "app DB missing: $QueueDb" }
function Invoke-QueuedSession {
  param([string]$Label, [string]$ModelFile, [string[]]$RunnerArgs,
        [string]$DbPath = $QueueDb, [ValidateSet('vulkan','hip')][string]$Backend = 'vulkan')
  $root = $QueueRoot
  $db = (Resolve-Path -LiteralPath $DbPath -ErrorAction Stop).Path
  $model = (Resolve-Path -LiteralPath (Join-Path 'D:\llm-models' $ModelFile) -ErrorAction Stop).Path
  $zip = (Resolve-Path -LiteralPath $QueueZip -ErrorAction Stop).Path
  $vendorName = if ($Backend -eq 'hip') { 'llama.cpp-hip' } else { 'llama.cpp' }
  $runtime = (Resolve-Path -LiteralPath (Join-Path $root "vendor\$vendorName\llama-server.exe") -ErrorAction Stop).Path
  $configPath = Join-Path $root "docs\gate-$Label.config.json"
  $manifestPath = Join-Path $root "docs\gate-$Label.manifest.json"
  $exportPath = Join-Path $root "docs\session-evidence-$Label.json"
  foreach ($path in @($configPath,$manifestPath,$exportPath)) { if (Test-Path -LiteralPath $path) { throw "refusing existing artifact: $path" } }
  $argv = @($RunnerArgs) + @('--backend',$Backend,'--request-cap-ms','300000','--ram-abort-gib','4','--db',$db)
  if ($argv[0] -ne 'H') { throw 'queued session must use scenario H' }
  $config = [ordered]@{
    snapshotHead=$QueueHead; cwd=$root; args=$argv; dbPath=$db; sourceZip=$zip
    tsxCli=(Join-Path $root 'node_modules\tsx\dist\cli.mjs')
    launcher=(Join-Path $root 'scripts\measurement-launcher.ts')
    runner=(Join-Path $root 'scripts\run-session.ts')
    exporter=(Join-Path $root 'scripts\export-session-evidence.ts')
    runtimeExe=$runtime; model=$model; exportOut=$exportPath
  }
  $bytes = [Text.UTF8Encoding]::new($false).GetBytes((ConvertTo-Json -InputObject $config -Depth 10 -Compress))
  $file = [IO.File]::Open($configPath,[IO.FileMode]::CreateNew,[IO.FileAccess]::Write)
  try { $file.Write($bytes,0,$bytes.Length) } finally { $file.Dispose() }
  $tsx = Join-Path $root 'node_modules\tsx\dist\cli.mjs'
  $launcher = Join-Path $root 'scripts\measurement-launcher.ts'
  & node $tsx $launcher --create $configPath $manifestPath
  if ($LASTEXITCODE -ne 0) { throw 'manifest creation failed; no launch' }
  & node $tsx $launcher --verify $manifestPath
  if ($LASTEXITCODE -ne 0) { throw 'manifest verification failed; no launch' }
  & node $tsx $launcher --launch $manifestPath
  if ($LASTEXITCODE -ne 0) { throw 'measurement or export failed; keep partial evidence and GPU HOLD' }
}
$Pin8B = '[{"model":"8B","ngl":999,"kv":"f16"}]'
```

Before calling the helper, inspect the released HEAD and manifest argv/model/runtime/export path. The helper is a recipe, not GPU authorization. Fable releases one item at a time after fresh process/env/RAM/adapter checks and at least 60 seconds idle. A failed run's `--resume` uses the session ID from that run's own log and a fresh label.
