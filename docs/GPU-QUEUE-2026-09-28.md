# GPU queue — command lines (2026-09-28)

S3 runs these one at a time, only after Fable/Astra releases each one. Only one GPU user at a time; nothing else starts while an item is running.
Durations are estimates from this host's measured speeds: 8B ≈ 90 t/s, 14B ≈ 54 t/s, Gemma-4 ngl 19 ≈ 29 t/s, Qwen3.8 ngl 49 ≈ 10 t/s at 8K.
Session ids are not fixed: take the id from the run's `session:started` log line. Ids shift with any failed launch (session 2 is a stale `running` row; session 5 is running). The evidence file name is the label, since the DB has no label column.

## Per item: snapshot → gate → launch → export

1. **Snapshot.** Make a `git archive` ZIP of the released HEAD and record its SHA-256. Extract it into a fresh directory. `git archive` omits the ignored runtime, so junction in `vendor` (plus `node_modules` and `models`) and record `vendor/llama.cpp/llama-server.exe` SHA-256 and the release tag b11208. Write `HEAD.txt`.
2. **Preflight (fail = do not launch).**
   - 0 `llama-server.exe` / `typeperf.exe` / `run-session` / `ab-spill` processes.
   - 0 environment keys whose uppercase is `GGML_CUDA_ENABLE_UNIFIED_MEMORY`, checked in Process, User and Machine.
   - RAM available ≥ 12 GiB.
   - RX 9070 XT dedicated in use ≈ 1.1–1.2 GiB. If it is higher, another app holds the GPU: wait.
   - 60 s GPU idle since the previous item.
   - The app DB **file exists**: `test -f "$DB"`. `openDb` silently creates a missing file, which gives an empty DB, ids from 1 and a failing `--resume`.
3. **Launch.** Use a node launcher with `shell:false`, `windowsHide:true`, and the argv **array** below: JSON arguments are single argv elements. Do not launch from PowerShell 5.1, which strips the inner `"` of native arguments. The lines below are Git-Bash quoting of the same argv. `$DB` is the resolved absolute path below (never `%APPDATA%`, which stays unexpanded in an argv array).
   - Every `run-session` item includes `--request-cap-ms 300000 --ram-abort-gib 4`.
   - **Prerequisite:** the bounds check (scripts/harness-limits.ts: cap ≤ 300000, floor ≥ 4) is enforced only once S3's wiring round is in the released HEAD. Until then, the flags apply unchecked.
   - `-lv 4` is not a flag here. LlamaCppBackend always passes `-lv 4 --metrics --cache-ram 0 -fit off --parallel 1`, and ab-spill's argv carries `-lv 4` for the load/device lines.
4. **Export (read-only)** after the process exits and teardown is verified:
   `npx tsx scripts/export-session-evidence.ts --session <id> --db "$DB" --head <HEAD> --out docs/session-evidence-<label>.json`.
   Then #3 audits it.
