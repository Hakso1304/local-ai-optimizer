# GAPS ranked

1. **HIGH — False confidence and wrong quality winners (I-5.1/2/6, I-7.4, I-8.3).** C:66–96 counts repeated samples as independent; E:100,229–253 compares marginal bands and retains Q contributions even while claiming quality is neutralized. A 10-item suite repeated three times loses its <30 warning and acquires a narrower band; near-equal candidates can still be separated by quality while the reason says speed decided. **Fix:** integrate uncertainty.ts, intersect testId+seed, use skill clustering, apply actual score neutralization, and persist the paired interval/decision basis.

2. **HIGH — Unverified hard constraints can produce a best candidate (I-1.1/2, I-6.0).** F:6,15 accepts estimated or cold metrics; C:14,118 assigns missing memory 50 and C:124 treats unavailable spill as no spill for penalty purposes; E:267 does not mark unavailable decisive inputs provisional. F:113 can call a rung spill-free when shared telemetry is absent. E:258 explicitly picks a failed-speed candidate if required context is reached, including when minDecodeTps was user supplied. N:107 returns it as best (though labelled fallback). **Scenario:** required 32K, explicit minimum 20 t/s, only 10 t/s candidate becomes best; missing spill telemetry can coexist with “no VRAM spill.” **Fix:** measured shared eligibility/safety predicates, unknown => not verified, separate unmet-constraint alternatives from any confirmed best.

3. **HIGH — Partial-offload veto can eliminate the only compliant configuration (I-7.6).** E:219 uses all usable full-offload candidates, not eligible alternatives. Full offload at 8K vetoes a partial config passing required 32K. **Fix:** veto only against same-model alternatives satisfying the identical measured hard constraints, recording that comparator in the verdict.

4. **HIGH — Infrastructure failures/truncation contaminate measured Q (I-5.7/8).** B:735,739 writes failures with no evaluationStatus; outputTruncated/maxTokens are not persisted. C:79 treats every resulting row as scored evidence and C:96 labels Q measured. A sandbox or template failure is counted against the model; a truncated but checker-matching answer can pass. **Fix:** persist evaluator status/token budget/truncation, quarantine affected comparisons, preserve valid performance separately.

5. **HIGH — Confirmed/provisional separation is absent and priors depend on competitors (I-1.2).** E:171 changes every higher prior to the lowest measured Q; E:224 mixes candidates and E:270 marks the whole result provisional even for an irrelevant missing-Q model. Adding a low-Q candidate can change another model's score. **Fix:** immutable priors, separate confirmed/provisional eligible lists, decisive-component provenance tracked per candidate.

6. **HIGH — Safety failures vanish from the explanation (I-0.1, I-6.3).** E:146 discards candidates with no usable row before interpret(E:293), which then cannot emit their guard/device-loss insights. S:45 replaces historical failed rows with retries. UI InterpretPanel.tsx:100 drops every alert after two. **Scenario:** a device loss followed by a successful retry and three critical insights can leave the reset absent or hidden. **Fix:** pass all persisted runs plus supersession/time metadata to interpretation; surface all critical insights independently of ranked candidates and warning cap.

7. **HIGH — Memory assurances use invented or wrong evidence (I-4.1/3/4/5).** E:441 uses zero for unknown in-use and omits planning reserve; E:459 hides floor deficits; E:447 claims reclaimable cache without observing unload; E:469 generalizes one peak into Windows spill behavior. **Fix:** persist planning basis/floor/credit and lifecycle observations, retain signed differences, evaluate >=3 pre-spill samples, otherwise say not evaluable/omit the claim.

8. **HIGH — Comparison identity and generation scope are unverified (I-7.1/5, I-8.0).** E:498 can call different fine-tunes the same quantized model; E:501 prefers smaller without matched hard constraints or margin. C:174 projects suite token splits onto another context; B:734 discards whether token counts were runtime-reported; src/core/benchmark/gen.ts:90 labels answerTokens/effectiveTps measured even when split came from characters. **Fix:** store base/file/template identities and applied request scope/source; block unsupported comparisons and preserve estimated provenance.

9. **HIGH — Coverage is presented as a proven machine limit (I-2.1/4/5).** R:13 calls <25% coverage “the usable limit” and warns even for a user-capped clean sweep; E:336 only emits a required-context problem if every model misses. **Fix:** separate largest clean tested, observed failure, planned skip and stop reason; report reached/failed/not-tested per model and make unsupported-ceiling wording a coverage note.

10. **MED — No decision trace; rule citations refer to the wrong normative rules (I-7.2).** R:2 remains interp-1; e.g. I-1.2 means unavailable-memory, I-5.7 means not-a-leaderboard, I-7.1 means winner, I-7.2 means why-not. A visible citation now points to a different v2 policy. T:328/N:164 omit trace and thresholdsUsed. **Fix:** version the catalog/schema together, migrate ID semantics, serialize evaluated constraints, eligible sets, component scope, paired intervals, neutralizations and actual tie-break path; render reasons from that trace.

11. **MED — Ranking and explanatory decisions still live outside verdicts().** `rg` over N found: lines 74–80 choose fastest/bestQuality/bestLongContext/lowestMemory directly; 123 chooses “quality over speed” attribution from a rate ratio; 135 sorts largest contributions; 145–150 choose which challengers are explained; 154–159 recompute generation deltas/speed/tolerance wording. These are not independently traceable rule verdicts even where called by verdicts. **Fix:** represent alternatives, context selection, attribution, normalization/penalties and tie breaks explicitly in versioned verdict/trace outputs. Explanation selection need not be a rank gate, but should not pretend to be the deciding verdict.

12. **MED — Uncited reason inventory.** N:31 headline has no rule ID; N:53 normal candidate whyNot is uncited unless a nested failure or conditional quality sentence happens to contain one; N:158 generation whyNot is always uncited; E:148 excluded reasons are raw cliff text or `no runs recorded`.
