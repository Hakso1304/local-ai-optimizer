# RANKED FINDINGS
**Q1 HIGH — cancellation can be lost between preprocessing and generation (all session/proof releases).** scripts/run-session.ts:204 aborts the session once; src/core/benchmark/session.ts:289 only cancels the currently active completion. In quality, the abort check at :1061 precedes awaited applyTemplate(:1070), followed by runPrompt(:1077) without another check. The guardedLoad poll at :982 returns once tripped. Scenario: RAM drops below 4 GiB while apply-template is pending; both guards cancel an empty completion slot, then generation starts and can run to its request deadline despite the latched abort. Ladder prompt sizing at :842 similarly precedes unguarded warmup(:853). Fix: propagate a persistent combined abort signal into every request, check after every await and before spawn/generation, and unload on RAM abort; apply this to long needle and future proof rendering too.

**Q2 HIGH — whole PID-chain teardown is not guaranteed (all releases).** scripts/ab-spill.ts:38 first kills only the parent and invokes taskkill /T only if that parent survives; runtime unloadModel at src/core/runtimes/llamacpp/index.ts:373 does likewise. A parent that exits promptly can leave a child alive and make cleanup succeed. Session sampler stop at src/core/telemetry/sampler.ts:289 kills without waiting; run-session.ts:240 merely prints a leftover count. Both external launchers' --launch branches have no signal forwarding/finally cleanup, and run-session.ts:243 exits on errors without a top-level owned-process cleanup boundary. Fix: track identity/creation time and descendants (prefer a kill-on-close Windows Job Object), await server and sampler closure, fail the gate on any survivor, and handle launcher/session cancellation and exceptional exit through the same cleanup.

**Q3 HIGH — “4 GiB watchdog on every path” is not enforced around probes or teardown (all releases).** run-session.ts:112,169 synchronous tasklist/git calls lack timeouts; :122 scans/probes before its watchdog exists(:204). A/B listDevices(:87) and tasklist(:100) block its event-loop watchdog for up to 30 s; HIP/iGPU initial device probes run before launch's watchdog. A/B finally(:247) stops monitoring before sampler/server teardown. Scenario: a stuck/allocating device probe or stalled OS command consumes the watchdog window while memory falls; session tasklist can hang indefinitely. Fix: bound every OS command, start supervision before preflight, use asynchronous abortable probes and retain supervision until reaping completes; an independent supervisor is needed for a hard RAM bound during blocked JS.

**Q4 HIGH — current/frozen quality evidence is not row-bound (quality/proof release blocker).** src/core/benchmark/session.ts:1081 probes only one successful item; :1143 broadcasts proof to every row (RECHECK5 P1). scripts/run-session.ts:83,105 records only configId, last 400 prompt characters, reply and stopType, with no stable item/sample/gen/render identity; :198 dumps that transcript, not a complete replay binding. Current scripts/prove-quality-rows.ts was absent when inspected. Fix locations/integration: (a) producer stores exact message/render hashes, item/instance/sample/gen/config/backend/build/template identity and requested/accepted sampling; (b) wrapper preserves full replay input or immutable content-addressed input plus raw response binding; (c) proof tool validates the original identity/seed/template, proves every exercised row/branch under the same guards, and writes an exclusive sidecar keyed by original row ID and payload hash; (d) exporter preserves originals and links proof-run HEAD/runtime/artifact hashes; (e) launcher/gate requires a fresh committed producer/proof snapshot, not frozen842d396; (f) interpretation rejects unbound proof. Re-rendering can establish template behavior, not retrospectively establish an unrecorded runtime-accepted seed or token split. Never rewrite old rows/recommendations as if the proof existed at generation time.

**Q5 MED — session artifacts lack the A/B/exporter's no-clobber and atomicity guarantees.** run-session.ts:189 derives a millisecond timestamp filename; :195 repeatedly opens it with truncating writeFileSync. A filename collision overwrites evidence; process termination during serialization/write can leave the only dump invalid. :237 cleanup/save is not in a top-level finally. Fix before evidence-producing release: exclusively reserve the output at startup, checkpoint through atomic replacement under that reservation, retain a valid previous checkpoint, and flush failure/abort metadata from finally. A/B and export-session-evidence.ts already use exclusive wx; do not replace those with truncating writes.

**Q6 MED — ZIP identity does not freeze the executed environment.** docs/calibration-stage3-preflight-2026-09-28.md:7 explicitly uses junctions; inspected Qwen snapshot node_modules and vendor/llama.cpp resolve to E:\Product_1's mutable directories. External launcher checks only existence/env and does not reverify hashes or the lease. A changed DLL/dependency after preflight can change execution without changing ZIP/HEAD. Fix at next gate: freeze dependency/runtime copies or enforce an exclusive no-mutation lease with complete manifest verification immediately before launch and after execution; record Node, dependency lock/install identity, launcher, exe/DLL and model hashes. ZIP alone is source provenance, not a complete reproducible runtime. Manually recorded gate checks currently provide protection the launcher itself does not enforce.

**Q7 MED — logging fix exposes a buffer-summary ambiguity, not a proven capacity limit.** scripts/ab-spill.ts:270 calculates largestBufferMiB over all parsed devices, including CPU/Vulkan_Host/ROCm_Host. With -lv4, a large host buffer can become the alleged largest device allocation if this field is reused for I-2.8 qualification. The adapter denominator is also hardcoded(:70), and the LUID is selected by greatest observed allocation(:253), not verified device identity. Fix before budget/capacity claims: separate host/device buffers and report selected physical adapter identity/total; never promote raw residency from this scalar. Plain raw A/B collection may proceed with these fields explicitly scoped as non-capacity evidence.

**Q8 MED — A/B health readiness does not bind requests to the owned model/server.** scripts/ab-spill.ts:185 chooses a random port; :220 accepts any successful /health without the production backend's /props model/config verification. A foreign listener/collision can answer health/completion before the spawned server's bind failure is observed. Fix before A/B release: reserve a loopback port and verify model/context/process ownership before warmup; treat conflict as failure and never kill the foreign listener.
