# REMAINING FINDINGS — RANKED, CONCRETE
**1 — HIGH: estimated fallback can become a permanent measured pruning limit without the required retry (I-4.0).** B:212–215 uses budgetFor's numeric value regardless of kind. With no observations, total15.92 GiB gives estimated12.74; fake rung dedicated12.5/shared1.08/adapter-free>3 GiB consequently has only0.24 GiB “room” and is not retried. Both runner versions executed **one load and persisted ceiling12.5 GiB** (B:421–427; current lines432–438). The fake second launch was configured to clear residency, but was never attempted. Thus an estimate indirectly decides an unverified event is capacity, becomes MEASURED, and can prune later allocations. **Fix:** estimates must not certify capacity or suppress the evidence-gathering retry; persist only qualifying observed post-retry capacity evidence, with its provenance.

**2 — HIGH: even a failed request creates a capacity observation.** Probe: first rung dedicated8/shared1.08 GiB, measured request times out. Both versions executed one load, persisted timeout row and **8 GiB ceiling**, with no placement retry. B:422 checks neither successful/valid measurement, completed retry, plateau nor failure kind; VramBudgetObservation/storage payload also lacks originating run/status/retry qualification (`src/core/storage/sessions.ts:24–32`). The transient failure can therefore shrink unrelated future plans indefinitely. **Fix:** require explicit valid capacity classification, linked attempts, measured scope and admissible failure semantics before learning; rejected/uncertain evidence must not enter the pruning table.

**3 — HIGH: non-comparable observations still prune, including allocations already capable of running clean.** C:168–174 falls back to the minimum of *all* observations when none has a comparable largest buffer, but labels it measured; C:230–232 applies it to pruning. Pure probe with unrelated100 GiB largest-buffer observation/6 GiB ceiling reduced full-offload f16 ladder **64K→16K** and q8 **128K→32K**, despite source text admitting “none with a comparable largest buffer.” There is no measured-clean exception or clean-observation envelope. Model/KV data are stored but ignored in comparability; C:226 uses aggregate weights/KV estimates as “largest buffer,” unlike B:203–208's individual runtime buffers. **Fix:** an uncomparable transfer is an estimate, not measured capacity for this allocation; do not prune from it, and protect observed-clean allocations with matched runtime/allocation identity.

**4 — HIGH: bounded retry can still hide persistent spill and contradict its learned result.** Probe dedicated8/raw shared1.08 GiB on both fresh launches: both runner versions made **exactly two loads**, saved both attempts, set placementRetry=true, and learned8 GiB. At a first rung there is no raw-growth predecessor to rescue cliff detection. This is inconsistent even internally: residency is considered capacity for learning but not spill for the rung/reason. **Fix:** reconcile post-retry evidence once for guard, persisted metric, cliff, learner and insight; persistent residency remains unresolved/capacity-suspect until established, never an unconditional placement conclusion. A retry that clears should retain the first event without treating it as a capacity ceiling.
