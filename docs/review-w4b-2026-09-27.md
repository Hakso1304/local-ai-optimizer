# W4B independent review — 2026-09-27

## STATUS

Complete. Only this new report and four new files under `tests/review-w4b/` were written. W4 tests and production files were not edited. No GPU, llama-server, benchmark, packaging build, or git commit was run. Network/download tests mock fetch and filesystem operations; sandbox tests launch only isolated Node children. Sources were being edited concurrently; references describe the inspected snapshot.

## SUMMARY

A demonstrated VM escape reaches the sandbox child process and forges a successful result; its filesystem/subprocess permission barriers remained denied.
Hub pagination leaks authorization to an arbitrary next-page host; download locking, filesystem boundaries, and stream-error handling have additional security gaps.
Four test files pass: 13 expected failures reproduce defects, five checks pass; renderer races and packaging lifecycle risks are also documented below.

## FINDINGS ranked

1. **HIGH — Error formatting escapes the VM and allows result forgery.** `src/core/quality/sandbox.ts:25,51-56`. **Scenario:** model code throws an object with a `message` getter. The child catch handler invokes it outside `vm.runInContext`; `Error.prepareStackTrace` exposes a host callsite function, whose constructor evaluates `return process` despite context string generation being disabled. The reproduction returned Node version `24.18.0`, then a second reproduction wrote the result marker plus `{ok:true,raw:"forged"}` and exited successfully. This reaches the sandbox child, not Electron main; checked `fs.read`, `fs.write`, and `child` permissions remained false. **Fix:** never access VM-thrown objects in host code; use fixed host diagnostics and perform any exception formatting within a bounded context, retaining the OS boundary. **Tests:** two `it.fails` and one permission-containment check.

2. **HIGH — The sandbox memory cap does not cover ArrayBuffer memory.** `src/core/quality/sandbox.ts:35`. **Scenario:** a child configured with `memoryMb:16` successfully allocates and touches a 64 MiB `Uint8Array`; `--max-old-space-size` limits V8 old space, not backing stores/RSS. Larger generated allocations can pressure the host before the timer terminates the child. The test is deliberately limited to 64 MiB. **Fix:** enforce a process memory limit with a Windows Job Object or equivalent OS isolation, including external/shared buffers. **Test:** `it.fails`.

3. **HIGH — Authorization can leave the approved HTTPS origin.** `src/core/hub/hf.ts:33-37,76-84,121-130`. **Scenario:** a listing response containing `Link: <https://outside.invalid/page>; rel="next"` causes the next request to include the saved Bearer token. Separately, an HTTP redirect to `http://huggingface.co/plain` retains authorization because `trusted` checks the host but not HTTPS. A malicious/compromised upstream response is the prerequisite; no live host was contacted. **Fix:** enforce an exact HTTPS origin allowlist before every authenticated request, including pagination and every redirect hop. **Tests:** two `it.fails`; cross-host CDN redirect stripping passes.

4. **HIGH — Download paths can escape through filesystem links.** `src/main/hub-logic.ts:34-38`; `src/core/hub/hf.ts:114-119,123,161`. **Scenario:** a junction inside an allowed destination points to another directory, or `model.gguf.part` is a symlink to an existing outside file. Lexical `resolve` checks pass; `statSync`/`createWriteStream` follow the link, and download can append to or truncate the outside file. **Fix:** validate real parent paths and reject reparse points/symlinks, then open the partial file with protection against link substitution.

5. **HIGH — Destination stream errors can crash Electron main.** `src/core/hub/hf.ts:161-178`. **Scenario:** a disk-full, access-denied, or failed-open event is emitted by the `WriteStream`; no `error` listener is installed. The surrounding async try/catch does not catch EventEmitter errors, and a wait for `drain` can also remain unresolved. **Fix:** use `stream.pipeline` or explicitly await/error-handle the writer, including open, drain, finish, and cancellation.

6. **HIGH — The one-download lock is claimed after an await.** `src/main/hub.ts:69,77,89-91`. **Scenario:** two calls enter while `listGgufFiles` is pending, both observe `active === null`, then both download to the same `.part`. Only the second controller remains reachable for cancellation; simultaneous writes can corrupt the download. Cancel during listing also has no active controller to abort. **Fix:** claim the operation/controller before the first await and release it in an outer finally covering lookup and disk checks. **Test:** `it.fails` demonstrates two downloader calls.

7. **HIGH — A second packaged instance can interrupt a live first instance.** `src/main/index.ts:29,34,67,281-289`; `package.json:49-67`. **Scenario:** installed and portable copies share the same production `userData`; there is no single-instance lock. Launching a second copy marks the first copy's running sessions interrupted and calls stale-server cleanup on its live PID file. Separate instances also bypass the in-memory benchmark/download locks. **Fix:** acquire a single-instance lock before database/PID cleanup, or isolate all state and verify process ownership per instance.

8. **MED — Cancel's delayed deletion can delete a replacement partial.** `src/main/hub.ts:105-109`. **Scenario:** cancellation closes download A, the user immediately resumes the same path as B, and A's fixed 500 ms timer removes B's new `.part`. The callback is neither tied to stream completion nor to an operation identity; deletion errors are uncaught. **Fix:** await A's completion and delete only its owned partial before allowing a replacement operation.

9. **MED — Resume accepts the wrong byte range and partials have no repository identity.** `src/core/hub/hf.ts:119,123,152-181`. **Scenario:** a three-byte partial receives `206 Content-Range: bytes 0-2/6`; appending three bytes makes the length six and passes without SHA256, although the range started at zero. Partials for two repositories with the same relative filename also collide. LFS SHA256 catches corruption when available, but non-LFS files have no such protection. **Fix:** verify the returned range starts at the requested offset and bind partial metadata to repository, revision/ETag, size, and expected hash. **Test:** wrong-range `it.fails`.

10. **MED — Windows alternate data stream names pass path validation.** `src/core/hub/hf.ts:114-117`. **Scenario:** `existing.gguf:hidden.gguf` passes the filename and containment checks and addresses an NTFS alternate stream rather than a normal model file. Such names can come from repository metadata on a different OS. **Fix:** reject Windows-reserved characters, device names, ADS syntax, and trailing-dot/space aliases for every segment. **Test:** `it.fails`.

11. **MED — Results and Dashboard accept stale asynchronous responses.** `src/renderer/src/ResultsPage.tsx:151-169`; `src/renderer/src/DashboardPage.tsx:75-80`. **Scenario:** select session A, then B; A's slower `getSession` reply overwrites B. Likewise, switching View As twice allows the earlier computation to win, and `shown` combines any `computed` with any `detail` without checking `sessionId` or workload. This can display/export A's recommendation alongside B's runs. Dashboard has the same workload-response race. **Fix:** attach a request generation/session/workload key and ignore stale responses; clear computed state while the current request is pending.

12. **MED — Hub resume uses the currently browsed repo, not the download's repo.** `src/renderer/src/HubPage.tsx:42-50,65,148`. **Scenario:** pause `owner/A/model.gguf`, browse `owner/B` containing `model.gguf`, then click Resume in the old transfer card; `download(target)` reads the new `repo` and can combine B with A's partial. Out-of-order `hubFiles` replies can also show A's files under B's heading; progress matching only compares the filename. Leaving/reopening the page loses transfer identity while the main download continues. **Fix:** store an immutable transfer key containing repo, revision, path and destination, match progress on that key, and reject stale listing replies.

13. **MED — Live events from another session replace the watched session.** `src/renderer/src/benchState.ts:48-64`; `src/renderer/src/main.tsx:31-35`. **Scenario:** while session `new` is displayed, a delayed `session:cancelled` for `old` changes both its ID and status; a late completion can also navigate App to the old Results page. **Fix:** accept a new ID only on an explicit session-start transition and ignore mismatched non-start events. **Test:** `it.fails`.

14. **MED — Previous-model measurements persist during the next model's load.** `src/renderer/src/benchState.ts:54-56`; `src/renderer/src/BenchmarkPage.tsx:118-124`. **Scenario:** after a fast model reports 100 t/s, `candidate:started` changes the model label but leaves `rate` and `telemetry` intact; the next model appears to own those numbers until new samples arrive. **Fix:** clear step-specific rates and telemetry on candidate/step transitions. **Test:** `it.fails`.

15. **MED — SLO defaults diverge from the session's effective requirements.** `src/renderer/src/ResultsPage.tsx:52`; `src/renderer/src/SloFilter.tsx:14-15,57-65`. **Scenario:** a custom `minDecodeTps:20` session is filtered with the base profile's threshold because the prop is never passed. Required-context and `large_coding` profiles make latency advisory, but SLO defaults enable a hard TTFT limit and mark an accepted winner outside constraints immediately. **Fix:** derive SLO defaults from the same effective profile, including custom decode and advisory latency. **Test:** advisory-latency `it.fails`.

16. **MED — A null in a chart bucket erases measured memory spikes.** `src/renderer/src/TelemetryChart.tsx:16-21`. **Scenario:** a downsampling bucket containing `[1,99,null,2]` produces only null, dropping the real peak. Intermittent counter gaps can therefore hide the spike associated with a guard abort/spill. **Fix:** preserve extrema and gap markers while respecting the point budget. **Test:** `it.fails`.

17. **MED — Estimated decode rates are presented as measured Pareto facts.** `src/renderer/src/SloFilter.tsx:23-30`; `src/renderer/src/ParetoChart.tsx:14-24,58`. **Scenario:** measured quality plus wall-clock-estimated decode is plotted as a configuration having a measured decode rate; `factsOf` discards the decode metric's provenance. **Fix:** retain provenance and exclude or distinctly label estimated axes in the chart/SLO facts. **Test:** `it.fails`.

18. **MED — Runtime installation has the same pre-await lock race.** `src/main/index.ts:109-118,215`. **Scenario:** two `runtime:install` calls enter before system scan/NVIDIA probing finishes; both see `installing === null` and can extract/delete the same runtime temporary directory. Benchmark/smoke entry points do not check `installing` either. **Fix:** claim a shared operation lock synchronously and make runtime mutation mutually exclusive with runtime use.

19. **MED — Disk preflight does not bound actual writes or check the file's actual volume.** `src/main/hub.ts:80-87`; `src/core/hub/hf.ts:163-181`. **Scenario:** a nested destination junction targets another volume, but free space is checked at `destDir`; alternatively a bad server streams more than the declared size, and the code detects the mismatch only after writing the entire response. **Fix:** check the resolved file parent volume, reject links as above, and stop writing immediately when bytes exceed the trusted expected length.

20. **LOW — Login can complete after logout and restore the saved token.** `src/main/hub.ts:37-44`. **Scenario:** login's `whoami` request is pending when logout clears credentials; the earlier login later writes its token back. API requests also have no explicit timeout, so this window can be long. **Fix:** invalidate pending login generations on logout and apply bounded request timeouts.

## CHECKED-OK

- **Token storage:** production uses `safeStorage.encryptString/decryptString`, refuses saving when encryption is unavailable, and returns only account metadata. There is no saved-token getter in preload. The user's freshly pasted token necessarily lives briefly in the password input/React state; it is cleared on successful login.
- **Redirect baseline:** ordinary download redirects to a different CDN hostname strip Authorization. Size and SHA256 are fetched by main from Hub metadata, not accepted from renderer download arguments. A failed SHA256 deletes the partial; a final filename is promoted only after checks.
- **Path baseline:** ordinary `..`, absolute-path and drive escapes are rejected by download resolution; `destDir` is restricted lexically to configured model roots. The link/ADS exceptions are findings above. `hub:files` validates repo syntax; `hub:download` checks only argument types and should reuse that validation before its listing request.
- **Disk baseline:** subtracting a normal same-volume partial from the space needed is valid: if Range is ignored, removing that partial frees the bytes needed to restart. The problem is actual-volume/size enforcement, not that arithmetic alone.
- **IPC inventory:** preload exposes named wrappers, not generic `invoke`, shell, or filesystem APIs. `system:scan`, `runtimes:detect`, `models:list`, `workloads:list`, `sessions:list`, settings reads, cancel/pause, and Hub account/dir actions take no meaningful renderer path arguments. `bench:start/resume` sanitize their requests; required context, decode bounds, reps, ladder and safety-margin overrides are constrained. Inherited-workload-name validation remains the already-reported W4 issue at this snapshot, not a new W4B finding.
- **IPC IDs/exports:** `sessions:get`, `telemetry:run`, `recommendation:compute`, and `bench:resume` coerce IDs with `Number` without positive-safe-integer validation; malformed IDs can reject or read no row, but SQL is parameterized and no SQL injection was found. `recommendation:latest` lacks workload validation. `file:save` checks content type/size and uses an OS save dialog before a write; no silent arbitrary export-write path was found.
- **Settings trust:** there is no IPC setter for arbitrary settings or `modelDirs`; workload/context setters preserve other fields. A locally edited settings file can broaden roots to system directories, and malformed JSON is not caught, so this file is trusted local configuration rather than a security boundary against another same-user process. No silent renderer-only way to inject `modelDirs` was demonstrated.
- **Required-context plumbing:** BenchmarkPage sends custom required context/minimum decode; the current `recommendation:compute` now passes stored requirements to `recommendForWorkload`. App owns live state across page changes. SLO defaults are the remaining mismatch documented above.
- **Null rendering:** `M`, live numeric helpers and ordinary line paths show gaps/dashes for null. Telemetry's `?? 0` is used only to choose axis bounds, not to draw missing samples as zero. Pareto explicitly excludes unmeasured quality, but fails to preserve decode provenance as reported. No separate `App.tsx` exists; App is in `main.tsx`.
- **Packaging/build resources:** config includes `out/**` and package metadata, with no `extraResources`, runtime/model bundle, or custom fuse configuration. Packaged runtime/model paths are writable userData locations; dev appends `-dev` before constructing state paths. Portable and NSIS both use production userData, which is not an isolated portable data folder. Sandbox depends on Electron's RunAsNode fuse remaining enabled; disabling it during future hardening requires replacing the child-launch mechanism. Installed binary fuse/ASAR behavior was not executed or claimed verified.
- **Quit/uninstall:** before-quit requests cancellation and synchronously kills the server; next launch marks unfinished sessions interrupted. It does not await full cleanup. NSIS retains userData and restricts its taskkill by both PID and image name, but has no creation-time ownership check or `/T`; a reused PID belonging to another `llama-server.exe` can still be killed. No installer was executed.
- **Sandbox containment:** prototype and async-function constructor probes were blocked on the normal evaluation path, `Atomics.wait` was interrupted, and hostile `NODE_OPTIONS` was not inherited. The demonstrated exception-object escape and backing-store memory bypass are separate from those passing checks. No filesystem read/write or subprocess permission bypass was demonstrated.
