# W4 independent review — 2026-09-27

## STATUS

Complete. Read-only review of the requested source and five prerequisite docs; only this report and `tests/review-w4/review.test.ts` were created. No runtime, GPU, or benchmark was run.

## SUMMARY

The highest risks are unguarded quality loads, cancellation during load, and a RAM guard that depends entirely on telemetry rows.
Six defects have executable `it.fails` reproductions; one sampler null-handling check passes.
The recommendation's normal sort is deterministic, and latest-run storage selection is correct, but quality persistence can become partial.

## FINDINGS (ranked)

1. **HIGH — Quality phase bypasses the memory safeguards.** `src/core/benchmark/session.ts:561-580` — After a safe ladder, `runQuality` loads the model again and sends up to 180-second requests with no live RAM check, sampler, or spill guard; other apps can consume RAM between phases and a large model can starve the host. The same applies to `runLongNeedle` at lines 537-555. **Fix:** run every load and request through the same live guard and pre-check used by `runStep`.

2. **HIGH — Cancel during load can take the full load timeout.** `src/core/benchmark/session.ts:167,328-335,422`; `src/core/runtimes/llamacpp/index.ts:249-263,423-425` — The abort handler calls `backend.cancel()`, which only aborts an in-flight request, while `loadCfg` never passes `signal` to `loadModel`; pressing Cancel while `/health` remains 503 leaves the server loading until its 120-second deadline. **Fix:** pass the session signal into every load and make cancellation unload the server immediately.

3. **HIGH — Zero or missing sampler rows disable the in-step RAM and spill guards.** `src/core/benchmark/session.ts:396-413,473-499`; `src/core/telemetry/sampler.ts:244-277` — If `typeperf` fails to start, emits no rows, or omits the RAM column on a localized Windows install, `flush` never trips and a large load continues despite available RAM falling below the floor; the metrics become unavailable only after the step. **Fix:** poll OS free RAM independently during load and requests, and fail safely when guard inputs cannot be read.

4. **HIGH — Failed process cleanup loses the only handle to a live server.** `src/core/runtimes/llamacpp/index.ts:282-296`; `src/core/benchmark/session.ts:361,258,323` — `unloadModel` sets `this.proc = null` before waiting; if `taskkill` fails and the child remains alive, it throws, but later cleanup sees no process and clears the PID file. The runner logs and continues to the next step. **Fix:** retain the process and PID file until exit is confirmed; treat cleanup failure as a hard session stop.

5. **HIGH — A partial quality suite can survive a failed write and be reused as complete.** `src/core/storage/sessions.ts:49-52,167-170`; `src/core/benchmark/session.ts:273-274` — `saveQualityResults` inserts 17 rows without a transaction; a crash or error after one insert leaves a subset, and resume accepts `stored.length > 0`, scoring the model on incomplete categories. The in-memory SQLite reproduction leaves one row after the second insert throws. **Fix:** insert the suite in one transaction and require the expected test IDs/version before reuse.

6. **MED — Unknown VRAM occupancy is budgeted as zero.** `src/core/benchmark/candidates.ts:159,203` — If the adapter's in-use counter is unavailable, an 8 GiB card with a 6 GiB model gets a full-offload candidate even if another app holds several GiB; the note explicitly says the budget assumes zero, and there is no live VRAM pre-check before loading. **Fix:** use the runtime's free-memory reading or a conservative bound, and defer the candidate when neither is known. (`it.fails`)

7. **MED — Partial-offload KV estimates ignore per-layer layout.** `src/core/benchmark/candidates.ts:65-87,95-113` — `kvLayout` correctly sums Gemma-4 per-layer heads and Qwen3.5 attention layers, but `estimateMemory` assigns GPU KV by `gpuLayers / layers`. With four layers having KV heads `[1,1,8,8]` and the final two layers offloaded, the GPU holds 16/18 of KV, while the estimate assigns 1/2. This can under-prune high-context Gemma-4 or hybrid Qwen3.5 probes. **Fix:** sum the KV bytes of the actual offloaded layer indices for GPU and CPU separately. (`it.fails`)

8. **MED — Inherited object keys pass workload validation.** `src/main/validate.ts:41`; `src/main/index.ts:92,123,146` — A renderer request with `workload: "__proto__"` passes `in WORKLOADS`; planning then receives an object without profile fields and can fail the session. **Fix:** use `Object.hasOwn(WORKLOADS, value)` (or a fixed ID set) in every IPC path. (`it.fails`)

9. **MED — A Vulkan device-loss signature is classified as an ordinary crash.** `src/core/runtimes/llamacpp/parse.ts:109-114`; `src/core/benchmark/session.ts:209-216,237` — A stderr tail containing `VK_ERROR_DEVICE_LOST` returns `crash`, so the runner does not set `gpuLost` and continues launching GPU candidates on a lost device. **Fix:** match underscore-separated Vulkan codes and add a regression fixture. (`it.fails`)

10. **MED — A negated needle passes retrieval quality.** `src/core/quality/checkers.ts:104-110` — The answer `The project name is not HELIOTROPE-5.` passes because the checker only searches for a substring, although it explicitly denies the correct answer. All three context tests use this checker. **Fix:** require an isolated answer equal to the needle, allowing only documented wrapping. (`it.fails`)

11. **MED — Lexical model-root validation follows links outside the root.** `src/main/validate.ts:8-12,44-47`; `src/main/index.ts:178-185` — A `.gguf` symlink inside a configured model folder can point outside it; `isInside` checks the link path, then smoke/load follows the link. **Fix:** compare resolved real paths for the file and allowed roots after verifying the file exists.

12. **MED — Missing llama timings do not yield the promised estimated TPS in normal runtime output.** `src/core/runtimes/llamacpp/parse.ts:36-53`; `src/core/benchmark/session.ts:501-509` — When the final SSE chunk lacks `timings`, `toPromptResult` sets prompt and decode token counts to null; session's wall-clock fallback requires those counts, so both TPS fields stay unavailable and a completed step is excluded. **Fix:** obtain token counts from the server tokenizer/stream count (or another measured count) before calculating estimated rates.

13. **LOW — One transient decode dip permanently lowers the practical ceiling.** `src/core/scoring/cliff.ts:54-64,96-108` — A sweep of 100, 60, then 100 t/s at 2K/4K/8K marks 4K as a cliff and 8K as beyond the limit, even though performance recovers; two reps are insufficient protection against a short competing workload. **Fix:** confirm a suspected single-step cliff with another rep or a recovery-aware rule before making the limit sticky.

14. **LOW — The latest recommendation can belong to an interrupted rerun.** `src/core/storage/sessions.ts:125-130,39-42` — A completed session's recommendation remains stored when its rerun begins; if the app dies, `latestRecommendation` can still return that row from a session now marked `interrupted`, while its latest run rows may have changed. **Fix:** select recommendations only from completed sessions or version them against the run set.

## CHECKED-OK

- `cliff.val` and `isUsable` reject null, non-finite, and zero decode rates; `peaks([])` returns null aggregates, never numeric zero.
- The normal recommendation ranks by eligible status, rounded score, memory and `configId`; no `Date` or `Math.random` enters this path, and profile weight insertion order is fixed.
- `LATEST_RUNS` selects the maximum row ID per `(configId, ctx)` within one session; SQLite row IDs are unique, so its outer `id IN (...)` does not cross sessions. Resume uses those rows and reruns cancelled/skipped steps.
- GGUF parsing retains Qwen3.5 `full_attention_interval`, Gemma-4 per-layer KV heads and sliding-window pattern; `kvLayout` uses them for total KV. The defect above is the subsequent GPU/CPU split.
- The calibrated smooth 8B and 14B spill patterns fit the current decode/shared thresholds. Zero telemetry samples remain unavailable in the result rather than being stored as zero.
- Quality `jsCodeAsync` runs model-written code in a separate permission-restricted, memory-capped child with a hard timeout. I found no demonstrated host escape in the reviewed sandbox path.
